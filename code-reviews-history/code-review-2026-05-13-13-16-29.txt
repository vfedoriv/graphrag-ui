  API Client boundary gaps — src/api/client.ts

  1. Network errors not caught (client.ts:27): fetch() can reject before any response (offline, CORS, abort). Callers get a raw
  TypeError: Failed to fetch instead of a normalized ApiError.
  2. JSON.parse unguarded on success path (client.ts:49): A malformed 200 body (truncated response, proxy HTML) throws a raw
  SyntaxError that leaks implementation details to users.
  3. ApiError is not an Error instance (types.ts, used throughout): The UI casts (err as Error).message everywhere. This works
  by coincidence today, but mixes undetectably with real TypeError network failures and will break instanceof Error checks in
  any future logging/monitoring integration.

  ---
  Important Issues (should fix)

  Table uses array index as key — src/shared/ui/Table.tsx:18

  Row deletion reuses DOM nodes because keys are positional. Combined with the uncontrolled <Input defaultValue={kb.name}> in
  KnowledgeBasesPage, deleting a row can leave the deleted row's text in the surviving input. Fix: accept a stable rowKey per
  row.

  KnowledgeBasesPage inline editor fires on every blur — :71

  onBlur fires a PUT even when the value didn't change. Also uses defaultValue (uncontrolled), so server-side rejections won't
  reset the field. Gate on e.target.value !== kb.name.

  EndpointTabs missing ARIA semantics — src/shared/ui/EndpointTabs.tsx:24

  Tab buttons have no role="tab", no aria-selected, no role="tablist" container. Tests currently disambiguate tabs from action
  buttons only by call order — fragile. WCAG violation.

  Input/Textarea use :focus not :focus-visible — Input.tsx:8, Textarea.tsx:8

  Button.tsx correctly uses focus-visible:ring-2. These two don't, inconsistently removing the keyboard focus indicator for
  mouse users and leaving no fallback ring. WCAG 2.4.7 violation.

  Stale localStorage KB ID not reconciled — src/shared/state/selectedKnowledgeBase.tsx

  A saved KB ID that no longer exists in the API response causes every feature page to fire requests against a deleted resource
  indefinitely. Clear selectedKnowledgeBaseId after useKnowledgeBasesQuery resolves if the ID isn't in the returned list.

  AppLayout and feature pages silently swallow query errors

  useKnowledgeBasesQuery, useSchemasQuery, and others are destructured as { data = [] }. On failure the UI shows "No data" or
  "Create one", actively misdirecting users. isError should be checked and a visible error state rendered.

  mutateAsync callers produce unhandled rejections

  KnowledgeBasesPage.tsx:35-39 (onSubmit) and QueriesPage.tsx:67 (generate) use mutateAsync without try/catch inside async
  callbacks. TanStack Query stores the error on the mutation object, but the unhandled rejection still fires and pollutes error
  monitoring. Add catch { /* surfaced via mutation.error */ }.
